## 怎么装（本地装载，现在就能用）

1. 打开 `chrome://extensions`，右上角打开**开发者模式**。
2. 点「加载已解压的扩展程序」，选中仓库里的 `LineTab/` 目录（**不是**外层目录，也**不是** ZIP）。
3. 新开一个标签页 —— 出来的就是 LineTab；打开即已聚焦搜索框，直接打字就行。
4. 权限只有「存储」一项；搜索（含 `g `/`b ` 前缀换引擎）、设置面板、`/` 聚焦、明暗三态都是活的。

> **三个容易踩的地方**：① **第一次接管新标签页时 Chrome 会弹一次气泡「改回 Google？ 此网页被扩展程序"LineTab"更改了」，请点「保持现状」** —— 点「改回原来的设置」就等于放弃 LineTab；② 若你已装过别的新标签页扩展，Chrome 只让一个生效，得先禁用另一个；③ 命令行侧载（`--load-extension`）只有 Chromium 支持 —— Google Chrome 与 Edge 都已移除这个开关，所以自动化测试用的是 Playwright 自带的 Chromium（`scripts/extension.spec.mjs`），而你手动装用的是 Chrome 本身，两条路互不影响。

> **为什么"打开即聚焦"要多一个 `focus.html`**：Chrome 把新建标签页的键盘焦点硬编码给地址栏（官方文档明说不要依赖页面拥有键盘焦点），所以界面要先从 `focus.html` 跳一次、变成"第二个文档"，`autofocus` 才真的生效 —— 这一跳肉眼看不见，地址栏显示的仍是扩展自己的 URL。详见「已知的坑」。

## 打包

`npm run pack` → 产出 `release/LineTab-1.0.0.zip`（版本号从 `manifest.json` 读，目录不存在会自动建）。打包器是手写的（`scripts/pack.mjs`，借 Node 自带的 `zlib.deflateRawSync` + `zlib.crc32`，没装任何依赖）：时间戳固定成 1980-01-01，所以**同样的输入永远产出同一串字节**；打完立刻把产物读回来自己解析一遍（条目名、顺序、CRC、内容逐字节比对）。**独立复核**：产物用 .NET 的 `Expand-Archive`（不是自己的解析器）解出来的 11 个文件与源文件 SHA256 全等，连打两次 ZIP 的 SHA256 也相同。

## 上架前还缺什么

- **商店素材**：1280×800 截图、宣传图、隐私说明（本扩展零网络请求，声明很好写）。这一步用户明确说先不做。
- **名字与简介长度**：商店上限是 `name` ≤ 45 / `description` ≤ 132 字符，`npm run check` 已经按这两个上限卡住。
- **「风格」这一行是留着的正式功能**：面板里的「风格」行与数字键 1–2 在 **A 纸白（默认）/ C 点阵**之间切，两套都长期保留。基线已按 `m03457` 定为 A 纸白，所以 `DEFAULTS.style` 不会再动。

## 已知的坑

- **本机网络**：`github.com` / `raw.githubusercontent.com` 解析被拦；npm 有腾讯云镜像所以装包正常，clone 仓库可能仍需代理。
- **渐变会出色带**：浅色整屏线性渐变在 1x 下肉眼可见横向 banding（已在 B 方案实测到）。零请求 + 纯 CSS 的前提下，纯色比渐变稳。
- **沙箱 ACL（已绕过）**：本会话曾出现 `SetNamedSecurityInfoW failed (Win32 5): grantWrite(D:\桌面\dsh)`；诊断结论是 `D:\` 根目录 owner 为 SYSTEM、当前用户无改权限能力，脚本按设计**拒绝越界修复**、未做任何改动。用户随后把会话文件策略改为完全权限，问题已绕过。诊断报告：`D:\桌面\dsh-acl-recovery\acl-report-bb7acc8ee81545d3b2677defdfda1e79.jsonl`（与本任务无关，仅备查）。
- **字体约束**：中文界面 + 运行时零网络请求 ⇒ 不打包 webfont，只能用系统字体栈。
- **PowerShell 5.1 的编码坑**：本机没有 `pwsh`（只有 Windows PowerShell 5.1），它会把**没有 BOM 的 UTF-8 `.ps1`** 当 ANSI 读——脚本里写死中文路径会变乱码（实测 `风格预览.html` → `椋庢牸棰勮.html`，页面根本没打开）。`.ps1` 必须存成 UTF-8 with BOM，或干脆不写中文路径。
- **`edit` 工具会剥掉 BOM**：改过一次 `.ps1` 后前 3 字节就从 `EF BB BF` 变成 `# =`，中文注释随之变乱码（本轮踩过一次）。改完 `.ps1` 记得补 BOM；现在这个脚本已不依赖中文路径，所以只影响可读性，不影响能不能跑。
- **别把旧产物当新成功**：生成/渲染前先删除目标文件，否则 `Test-Path` 会把上一轮的旧图当成本次成功，输出假的 OK（本轮真发生过，只能靠核对时间戳与哈希发现）。
- **渲染参数是 `-Shots`**（不是 `-Styles`），每项可带 `+dark` / `+panel` 后缀，例如 `-Shots paper,'grid+panel'`。
- **浮起层不许复用 `--surface`**：某个风格可能把 `--surface` 定义成 `transparent`（C 点阵就是），面板、弹层这类"必须不透明"的表面要单独用 `--surface-raised`（本轮真踩过：点阵从面板里透出来，是代码审查逐像素比对才发现的）。
- **暗色层别硬写风格专属的令牌**：当初暗色选择器带 `:not([data-style="night"])`、特异性 (0,2,0) 高于 `[data-style]` 的 (0,1,0)，一旦在里面写死 `--search-bg`，B/C 精心去掉的卡片就会在暗色下长回来（本轮真踩过）。删掉 B/D 之后这个选择器简化成 `[data-theme="dark"]`（(0,1,0)），与 `[data-style]` **同权**，谁赢只取决于源码顺序 —— 纪律照旧：共用骨架只写"所有风格共有"的差异，且必须留在所有 `[data-style]` 块**之后**；某个风格要保留自己的身份，就在骨架之后按风格族再写一条覆盖 —— 覆盖写成 `[data-theme="dark"][data-style="xx"]`（(0,2,0)，比骨架多一个属性选择器、一定赢，位置只是可读性）。现在 C 点阵就是这么干的（`--bg` / `--dot` 换成暖墨纸那一组，`m02694`）；A 纸白不需要覆盖块，它的暗色差异本来就在共用骨架里。
- **删风格族要顺手删"存档里的风格名"**：`mist`/`night` 删掉之后，老用户的 `localStorage` 里可能还留着这两个字符串，直接拿去写 `data-style` 会变成一个**没有任何样式命中的属性值**（页面看上去"掉了皮"）。所以 `loadSettings()` 里用 `STYLES` 白名单校准，落回默认值；`tmp/probe-stale-style.mjs` 就是这条的哨兵（同时验证有效值 `grid` 不被误伤）。
- **改 `.ps1` 之后必查 BOM**：`edit` 工具会把 UTF-8 BOM 剥掉，PowerShell 5.1 随即把中文读成乱码、脚本**直接解析失败**（本轮又踩一次）。补法：`[System.IO.File]::WriteAllText($p, $text, (New-Object System.Text.UTF8Encoding $true))`。
- **只改 hash 不会重跑脚本**：`page.goto('file://…#a')` 之后紧接着 `goto('file://…#b')` 是同文档导航，页面不会重新加载、JS 不会重跑，于是探针会读到上一个镜头的值（我写的 `tmp/probe-dark.mjs` 第一版就这么假绿过：四套暗色读出完全一样的令牌；`tmp/probe-dots-applied.mjs` 也踩过同一个坑）。要么每个镜头换新 page/context，要么 goto 之后补一次 `page.reload()`，要么给 URL 挂一个变化的查询串（`?case=1#grid`）强制真加载。测试文件里是每条用例一个全新 page，所以不受影响。**注意这条对页面自己的行为也成立**：`newtab.js` 只在加载时读一次 hash（没有 `hashchange` 监听），所以在已经打开的标签页地址栏里敲 `#grid` 不会立刻生效，得刷新一次 —— 视觉回归是"带着 hash 加载"，所以不受影响。
- **lint 的两点边界**（写代码时心里要有数）：① 自定义属性的**声明**（`--x: #c00`）不受任何规则约束，绕过方式由 `scripts/check-tokens.mjs` 兜住；② 契约只锁"设计身份"类取值（颜色/圆角/字体/阴影/动效），间距与尺寸类几何值故意不锁。
- **白名单与黑名单的属性正则必须共用同一组常量**：它们曾各写各的，结果单边 `border` 简写（`border-top: 2px solid #c00`）整条漏网——第三轮审查才抓到。以后新增受管属性，只改 `stylelint.config.mjs` 顶部那组常量。
- **Playwright 不要跑 `npx playwright install`**：那一步走 playwright 的 CDN，本机 github 被拦会失败。配置里用 `channel: 'chrome'` 复用本机已装的 Chrome 即可（实测 `npm install` 只装 3 个包、5 秒完成，全程没有浏览器下载）。

- **基准图路径含 `{platform}`**：本机是 `scripts/__screenshots__/win32/`；换机器/换平台各自生成，不会互相覆盖。若将来接入 MV3 实机测试线（`channel: 'chromium'` + `launchPersistentContext`），要给那条线单独的目录或 project 名，别和这套静态页镜头撞名。
- **根目录已经有好几个 html 了**（`Preview.html`、`设计提案二.html`、`设计细节.html`、`细节体验.html`、`全局设计.html`、`风格扩充探索01.html`）：`scripts/render-preview.ps1` 不传 `-Page` 时只取"找到的第一个 html"，出图必须写清楚，例如 `& .\scripts\render-preview.ps1 -Page .\设计提案二.html -Out .\tmp\proposals2 -Shots 's3+bare'`。顺带：给真页面出图时用 `-Out .\tmp\newtab`，别覆盖看稿页的手验图。

- **时钟已删，截图不再需要冻结时间**（本轮改动）：原先 `newtab.html` 显示真实时间，直接截图每次都不一样（必然假红），所以测试里要 `page.clock.setFixedTime(new Date(2026, 2, 6, 9, 41))` 并断言 `#clock` 正好是 `09:41`。时钟拿掉之后这条约束随之消失（`newtab.spec.mjs` 里的 `FROZEN` 与两条时钟断言已一并删掉）。**以后若把时钟加回来，记得同步恢复冻结时间**，否则截图必然假红。
- **两套 spec 的截图文件名不能撞**：都放 `scripts/__screenshots__/{platform}/` 下，看稿页用 `paper.png`、真页面用 `newtab-paper.png`；撞名会互相覆盖基准图，表现成"另一套测试无故变红"。
- **`chrome.storage.sync` 有配额**：`MAX_WRITE_OPERATIONS_PER_MINUTE` 是 120 次/分钟、`…PER_HOUR` 是 1800 次/小时，超了会让这次写入**失败**（不是排队）。所以：写入按 200ms 合并（面板里连点几下只写一次），按住数字键不放也不能让它一直写 —— 三处循环键都加了 `if (event.repeat) return;`。写失败只 `console.warn`，不弹窗、不阻塞界面。
- **已有新标签页扩展时会互相抢**：Chrome 只让一个扩展覆盖新标签页，装了两个就只有一个生效（也可能谁都不生效）。遇到"改了没反应"先看 `chrome://extensions` 里是不是有另一个新标签页扩展还开着。
- **合并窗口内页面消失会丢写入**（第二轮 `code_review` 抓到的真缺陷）：200ms 的合并定时器还没到点，用户就关标签页或按回车去搜索，那次改动就没了；而当时读回只在 sync 完全没有值时看镜像，所以**丢了不会自愈**（实测：切完风格 18ms 关页 → 重开还是旧风格；等 627ms 再关就正常）。两道防线一起上：① 两份存储都记 `savedAt`、读回取较新的那份（sync 失败或者慢的时候镜像能顶上）；② `pagehide` 与 `visibilitychange(hidden)` 时把没发出去的写入 flush 一次。T7/T8 就是这两条的哨兵，用 `page.clock.install()` 冻结计时器把"窗口期"变成确定时序，不靠"跑得够快"来赌。
- **命令行侧载只有 Chromium 支持**：Google Chrome 与 Edge 已经移除 `--load-extension` / `--disable-extensions-except`（官方文档与实测一致），所以真扩展测试用 Playwright 自带的 Chromium（本机 `%LOCALAPPDATA%\ms-playwright\chromium-1208`，`scripts/extension.spec.mjs` 自己找最新那一个）。**用户手动装走 Chrome 本身**（图形界面的「加载已解压的扩展程序」没有被移除），两条路互不影响。
- **新建标签页的键盘焦点被 Chrome 硬编码给地址栏**（`m03762` 用户报的 bug，根因不在我们代码里）：官方文档（Override Pages）明说"不要依赖页面拥有键盘焦点"，`document.hasFocus()` 会返回 `true`、`activeElement` 就是输入框，**但按键进的是地址栏**，页面连 `keydown` 都收不到。唯一可行的绕过是官方给的"两跳"：覆盖页指向一个只做 `location.replace()` 的 `focus.html`，真正界面在第二个文档里 + `<input autofocus>`（旧写法是同效的自导航 `if (location.search !== "?x") location.search = "?x"`）。另外首次接管新标签页时 Chrome 会弹一次「**改回 Google？**」气泡（按钮是「改回原来的设置」/「保持现状」，**必须选后者**），气泡在的那一轮按键会打进气泡，**会让实验得出错误结论** —— 要先用键盘选「保持现状」并让 profile 优雅落盘，再另开一个标签页做测量。`m01157` 起补一条纪律：页面里任何「把光标塞回 `#q`」的代码都算破规矩 —— 光标的来源只留两条（新标签页自动、点搜索框），面板开合、点引擎标签、Esc 都不许动它；唯一例外是 `window` 的 `focus` 兜底，而且第一次点/按键就解除。
- **Playwright 抓不到"浏览器 UI 抢键盘"这类 bug**：`page.keyboard.type()` 走 CDP `Input.dispatchKeyEvent` **直接派发给渲染进程**，绕过了浏览器 UI 的焦点路由，所以 `extension.spec.mjs` 里"直接打字进 `#q`"永远绿。这类问题只能用**真窗口实验台**验：`tmp/omnibox/run.ps1`（有头 Chromium + `SendKeys` + 前台窗口句柄守卫防误击 + `EnumWindows` 整窗截图）配 `probe.mjs`（CDP 读 `hasFocus`/`activeElement`/`qValue`）。判据只能是"**按键有没有落到 `#q`**"（`qValue` 变了没有），不能看 `hasFocus()`。
- **`npx playwright install` 在本机会失败**：它从 playwright 的 CDN 下载浏览器，实测 `ECONNRESET`；而 `chromium-1208` 已经存在且**够用**（扩展能装、`chrome.storage.sync` 能用、`chrome://newtab/` 能被接管）。所以扩展测试是"在已有安装里找"，不是"下一个新的"。
- **扩展测试的 profile 目录不能复用**：`freshProfile()` 原先删掉再建同名目录，Windows 上上一次的 Chromium 还没退干净就会把旧状态写回新目录里（表现为 T3 莫名带着上一轮的"默认引擎 = Google"）。现在目录名带 `pid` + 时间戳 + 随机后缀，每轮开头整棵清一次。**同一条对 `tmp/check-probe/` 也成立**（`cpSync` 覆盖已存在文件会报 `Error: , The operation completed successfully. … syscall: 'unlink'`；`rmSync` 有时静默不删）。
- **PowerShell 5.1 会毁了没有 BOM 的 UTF-8 源码**：`Get-Content -Raw` / `Set-Content` 对无 BOM 的 UTF-8 默认按 ANSI(GBK) 解码，一读一写就把中文注释变成乱码 —— 脚本语法仍然"合法"、行为却变了（实测因此让自动聚焦失效，得出过两次**假结论**：以为 T5 非空洞、以为 T4 真红）。**改 `.js` / `.css` / `.html` 一律用 `edit` 工具**，或用 `[System.IO.File]::ReadAllText($p,[Text.Encoding]::UTF8)` + `WriteAllText(..., New-Object System.Text.UTF8Encoding $false)`。
- **别用静态属性写断言**：`newtab.html` 的 `<html data-style="paper">` 是写在 HTML 里的静态值，刷新后**不等 JS 跑完**它就已经是 `paper` —— 对着它断言等于什么都没测（T5 第一版就是这么绿的）。要测"存储里的值真的进了 DOM"，必须同时做一次**正面控制**（存 `grid` 就要看到 `grid`），并在断言前等一个"只有 `init()` 跑完才会出现"的信号（这里用的是 `#q` 已聚焦）。
- **本地测试全绿不等于扩展能用**：`manifest` 写错、页面引用了白名单外的文件、混进一段内联脚本，静态页测试一条都不会红 —— 只在 `chrome://extensions` 里加载失败的**那一刻**才暴露。这就是 `npm run check` 存在的理由（纯 Node、几毫秒）。
- **运行文件挪进 `LineTab/` 之后，路径有五处要跟着走**（本轮实测踩到的）：① 五个探索页的 `<link href="tokens.css">` 要改成 `href="LineTab/tokens.css"` —— 不改的话它们会静默失去全部样式，而 [Preview.html](../design/Preview.html) 的视觉基准图会当场变红（这正是本轮发现它的方式）；② stylelint 的 glob 要写 `"*.css" "LineTab/*.css"`；③ `check-tokens.mjs` 的扫描目录与令牌文件路径；④ `newtab.spec.mjs` / `extension.spec.mjs` / `pack.mjs` / `make-icons.mjs` 的输入目录；⑤ `render-preview.ps1` 传的 `-Page`。路径常量只在 [scripts/runtime-files.mjs](../scripts/runtime-files.mjs) 里定义一次（`EXT_DIR`），其余脚本都从那里取 —— 再挪目录只改这一处。
- **令牌体检会拦住「脚本写了、`tokens.css` 里没声明」的运行时变量**（`m03794` / `m04538`）：滑块那截进度是脚本按 `min/max/value` 算出来的 `--slider-frac`（`m04538` 之前叫 `--slider-pct`），只在 `preview.css` 里用、由 `paintParam()` 写在元素的行内样式上 —— 体检仍要求它在 `tokens.css` 里有一个「家」（先声明 `--slider-frac: 0.5`），否则报悬空令牌。
- **别把一条注释的头两行换掉、留住它的尾巴**（`m03794`）：给 D1 那段注释加抬头时把自己的 `*/` 提前写上了，原注释的后续几行就落到注释外变成裸文本 —— **stylelint 照样 exit 0**，但浏览器的 CSS 解析被带偏，紧跟其后的 11 条 `@property` 全部没注册（实测 `getComputedStyle(stage).getPropertyValue('--bg')` 回到原始 hex `#faf9f5`，而不是插值出的 `rgb(250, 249, 245)`）。改注释要整段替换。

- **量具里写死的期望值会随被测参数漂移**（`m05406` 踩到）：`tmp/probe-knob-align.mjs` 原先按 `7 + frac × (W − 14)` 自己算"期望的填充右端"，滑块头一从 14px 变成 10px，点阵那几行就差了 1.36px 判 FAIL —— 产品和 DOM 都是对的，错的是量具。改成"判据用 **DOM 实测的头心**，公式另算一列按恒等式查（差 ≤0.05）"之后，换任何头大小都不会误判。凡是"探针自己算一个期望值再比对"，先问一句：这个常数会不会跟着被测对象一起变。
